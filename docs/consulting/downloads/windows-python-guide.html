처음 실행하는 수강생을 위한 안내입니다. 준비된 환경이 있다면 완료 여부를 확인하고 다음 단계로 넘어가세요. 각 단계의 결과를 확인한 뒤 다음 단계로 진행합니다.

참고자료. Windows 설치와 실행 길잡이

처음 실행하는 분은 여기서부터 순서대로 따라 합니다.

이 안내는 Windows에서 앱을 직접 실행하려는 수강생을 위한 참고자료입니다. 이미 앱이 정상 실행되면 재설치하지 않습니다. 4차수 ZIP을 예로 사용하지만 2·3차수도 해당 ZIP의 app.py 폴더에서 같은 순서로 실행합니다. 처음에는 설치와 실행이 별개라는 점부터 확인하세요.

먼저 내 컴퓨터에 Python이 있는지 확인합니다

  • 시작 메뉴에서 PowerShell을 검색해 엽니다.
  • 아래 두 명령을 한 줄씩 입력하고 Enter를 누릅니다.
py -3.12 --version
python --version
보이는 결과다음 행동
둘 중 하나가 Python 3.12.x이미 설치됨. 압축 해제 단계로 이동
명령을 찾을 수 없음·Store가 열림·다른 버전다음 페이지의 설치 안내 확인

>>>가 보이면 Python 내부입니다. exit() 후 PowerShell에서 명령을 입력합니다.

PowerShell은 명령을 입력하는 창이고 Python은 코드를 실행하는 프로그램입니다. Python이라는 시작 메뉴 앱을 직접 열어 나온 >>>에 pip 명령을 쓰지 않습니다. py가 없어도 python --version이 3.12.x라면 기존 설치를 사용할 수 있습니다. 다른 Python 버전을 삭제할 필요는 없습니다.

Python이 없으면 공식 설치 관리자를 준비합니다

  • 아래 Python 공식 Windows 다운로드 페이지를 엽니다.
  • Python install manager 항목의 공식 설치 파일을 선택합니다.
  • 다운로드한 설치 파일을 열고 설치를 진행합니다.
  • 설치가 끝나면 기존 PowerShell을 닫고 새로 엽니다.

Python 공식 Windows 다운로드 페이지

설치 관리자는 Python 버전을 설치하는 도구입니다. 다음 단계에서 수업용 3.12를 선택합니다.

공식 페이지에서 안내하는 Install manager를 사용합니다. Windows 앱 설치 창에서는 설치 또는 Install을 선택하며, 학교 PC에서 설치가 차단되면 담당자에게 요청합니다. ZIP 형태의 embeddable package는 이 수업의 설치 경로가 아닙니다. 이미 Microsoft Store 등에서 Python 3.12를 설치해 정상 확인한 학생은 이 단계를 건너뛰어도 됩니다.

수업용 Python 3.12를 설치하고 확인합니다

한 줄씩 입력하고 Enter
pymanager install 3.12

설치가 끝나면 아래 명령으로 확인합니다.

설치 확인 명령
py -3.12 --version

정상 결과: Python 3.12.x. 끝의 숫자는 설치 시점에 따라 다를 수 있습니다.

Python 공식 Windows 설치·버전 선택 안내

새 설치 관리자의 pymanager 명령은 예전 py 실행기와 이름이 겹치는 문제를 줄여줍니다. py 확인만 실패하면 pymanager exec -V:3.12 --version으로 확인할 수 있습니다. pymanager 자체를 찾지 못하면 새 PowerShell을 열었는지와 관리자 설치 완료 여부를 먼저 확인합니다. 본 실습 파일은 Python 3.12에서 실행 검증했습니다.

ZIP은 압축을 풀고 안쪽 실습 폴더를 엽니다

4차수 실습 ZIP 다운로드
  • 다운로드한 ZIP을 우클릭하고 ‘모두 압축 풀기’를 선택합니다.
  • 찾기 쉬운 폴더에 풀고 week-04-practice 폴더를 엽니다.
  • app.py, analysis_core.py, requirements.txt, data가 보이는지 확인합니다.

ZIP 안에서 파일을 직접 실행하지 않습니다. app.py가 보이는 폴더가 작업 위치입니다.

예를 들어 문서 폴더 아래 통계실습 폴더를 만들 수 있습니다. 경로에 한글이나 공백이 있다는 이유만으로 바꿀 필요는 없으며, 명령에 직접 경로를 적을 때는 따옴표로 감쌉니다. 압축 해제 결과에 바깥 폴더가 한 겹 더 있을 수 있으므로 실제 app.py가 있는 안쪽으로 들어갑니다.

탐색기에서 실습 폴더의 PowerShell을 엽니다

  • app.py가 보이는 탐색기 창의 주소창을 클릭합니다.
  • 주소창에 powershell을 입력하고 Enter를 누릅니다.
  • 열린 창에 아래 명령을 입력합니다.
한 줄씩 입력하고 Enter
Get-Location
Get-ChildItem

정상 결과: 현재 위치가 실습 폴더이며 파일 목록에 app.py와 requirements.txt가 있습니다.

주소창에는 검색창이 아니라 폴더 경로가 보이는 윗부분을 사용합니다. 바탕화면이나 사용자 홈 폴더에서 명령을 실행하면 app.py를 찾지 못합니다. 다른 위치라면 창을 닫고 탐색기에서 실제 파일이 있는 폴더를 다시 연 뒤 이 방법으로 PowerShell을 시작하세요.

이 폴더 전용 가상환경을 만듭니다

한 줄씩 입력하고 Enter
py -3.12 -m venv .venv

만들어진 환경의 Python을 확인합니다.

완료 확인
.\.venv\Scripts\python.exe --version

정상 결과: .venv 폴더가 생기고 Python 3.12.x가 표시됩니다.

가상환경은 이 실습에서 쓸 패키지를 따로 보관하는 공간입니다. py가 없지만 python --version이 3.12.x라면 첫 명령 대신 python -m venv .venv를 사용합니다. 설치 관리자 경로라면 pymanager exec -V:3.12 -m venv .venv도 사용할 수 있습니다. 이 대안은 하나만 선택합니다. 이미 .venv가 있고 버전 확인까지 성공하면 다시 만들지 말고 패키지 단계로 갑니다.

가상환경 안에 필요한 패키지를 설치합니다

한 줄씩 입력하고 Enter
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

설치 명령이 끝난 뒤 아래 명령으로 확인합니다.

설치 내역 확인
.\.venv\Scripts\python.exe -m pip show streamlit

정상 결과: Name: streamlit과 Version, Location이 표시됩니다. .venv 폴더만 있어서는 앱이 실행되지 않습니다.

설치 중에는 명령을 연속으로 더 입력하지 말고 PowerShell 입력 표시가 돌아오는지 확인합니다. Successfully installed 또는 Requirement already satisfied가 나타날 수 있습니다. ERROR로 끝나면 아직 설치 완료가 아닙니다. 같은 폴더에서 같은 .venv의 Python으로 설치하고 실행해야 다른 환경에 설치되는 혼동을 줄일 수 있습니다.

앱을 실행하고 표시된 주소를 엽니다

한 줄씩 입력하고 Enter
.\.venv\Scripts\python.exe -m streamlit run app.py
  • 터미널에서 Local URL 또는 URL을 찾습니다.
  • 브라우저가 열리지 않으면 표시된 주소를 복사해 주소창에 넣습니다.
  • 보통 http://localhost:8501 이지만 실제 표시된 포트를 우선합니다.

PowerShell 창을 닫지 마세요. 이 창에서 앱 서버가 실행 중입니다.

Streamlit 공식 설치·앱 실행 안내

app.py를 더블클릭하거나 python app.py만 입력하는 방식 대신 Streamlit 실행 명령을 사용합니다. 파일을 고친 뒤에는 실행 중인 앱에서 변경을 확인합니다. localhost는 자기 컴퓨터를 뜻하므로 이 주소를 다른 수강생에게 보내도 내 앱이 공유되지는 않습니다. 공유는 본문의 웹 배포 단계에서 다룹니다.

8행 수치가 보이면 첫 실행이 완료되었습니다

화면에서 할 일기대 결과
왼쪽 실습 데이터 선택8행 검증 자료

4차수 필터를 0–11로 변경4명 · 이탈50.0% · 평균50.0 CU

앱을 종료하려면 PowerShell에서 Ctrl+C를 누릅니다. 브라우저 탭만 닫아도 서버는 남아 있을 수 있습니다.

처음 100행이 선택되어 있으면 100명·21.0%·71.6 CU가 보이는 것이 정상입니다. 8행을 선택한 뒤 비교합니다. 카드가 뜨는 것뿐 아니라 표와 차트도 나타나는지 확인하세요. 화면을 닫은 뒤 다시 실행할 때는 다음 페이지의 절차를 따릅니다.

다음 수업에는 설치를 반복하지 않습니다

  • 같은 위치의 실습 폴더를 열고 PowerShell을 엽니다.
  • 아래 앱 실행 명령을 입력합니다.
  • 브라우저에서 터미널에 나온 주소를 엽니다.
한 줄씩 입력하고 Enter
.\.venv\Scripts\python.exe -m streamlit run app.py

처음: Python 준비·가상환경·패키지 설치·실행. 다음부터: 같은 폴더에서 실행. 파일에 필요한 패키지가 바뀌면 설치를 다시 확인합니다.

폴더를 다른 위치로 옮기면 기존 가상환경이 작동하지 않을 수 있습니다. 가능하면 같은 폴더를 유지하고, 옮겨야 한다면 앱과 데이터는 보관한 채 새 위치에서 환경을 준비합니다. 정상 실행 중인 앱에 같은 명령을 또 입력하면 다른 포트가 사용될 수 있으니 먼저 기존 화면을 확인합니다.

명령을 찾을 수 없으면 입력 위치부터 확인합니다

보이는 상황의미와 해결

py를 인식할 수 없음실행기 없음. python --version이 3.12면 해당 명령 사용

이 안내는 환경 활성화 명령 없이 실행합니다. 실행 정책을 바꾸지 않아도 됩니다.

py 명령이 없다고 Python 자체도 없다고 단정하지 않습니다. 이번 교수자 PC도 py 없이 Microsoft Store Python이 있었습니다. 버전이 확인된 Python으로 환경을 만들고, 그 뒤에는 .venv의 실행 파일을 직접 지정하는 방식이 공통 경로입니다. py와 python 둘 다 안 되면 설치 단계로 돌아가세요.

No module named streamlit은 패키지 설치를 확인합니다

Python은 실행됐지만 그 환경에 Streamlit이 없다는 뜻입니다.

한 줄씩 입력하고 Enter
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip show streamlit

두 번째 명령에서 설치 내역을 확인한 뒤 앱 실행 명령을 다시 입력합니다.

실제로 이번 교수자 PC에서는 .venv가 만들어져 있었지만 Streamlit이 없어 실행이 실패했습니다. pip만 따로 실행해 다른 Python 환경에 설치하지 않도록 같은 .venv의 Python을 지정합니다. 네트워크 오류, 버전 오류, 권한 오류로 설치가 실패하면 마지막 ERROR와 그 앞의 설명을 남기고 도움을 요청합니다. 인증서 검증을 끄거나 확인 없이 버전을 바꾸는 방식으로 해결하지 않습니다.

오류가 난 창을 닫기 전에 마지막 오류 문구와 실행 명령을 함께 확인합니다.

브라우저가 자동으로 안 열리는 것과 서버가 실행되지 않는 것은 다릅니다. 터미널에 오류 없이 URL이 나왔는지부터 확인하세요. 8501이 이미 사용 중이고 다른 앱을 방해하면 기존 프로세스를 임의로 종료하지 말고 자신의 실행 상태를 확인합니다. 실행 창이 종료되면 localhost에도 접속할 수 없습니다.

폴더를 옮긴 뒤 환경이 깨졌다면 도움을 요청합니다

  • Unable to create process는 .venv가 참조하는 Python 경로 문제일 수 있습니다.
  • 앱·데이터 파일을 보관하고, 폴더 이동·Python 변경 여부를 확인합니다.
  • 실행 환경은 컴퓨터와 경로에 연결되므로 다른 PC의 .venv를 복사하지 않습니다.
  • 도움 요청 시 실행 명령·오류 원문·현재 폴더·Python 버전을 함께 전달합니다.

정상 파일이나 Python을 무작정 삭제하지 않습니다. 환경 재구성이 필요하면 담당자와 확인합니다.

Python 공식 가상환경·경로 안내

이 오류에는 가상환경이 가리키는 Python이 없어졌거나 접근할 수 없는 등 여러 원인이 있을 수 있습니다. 교수자 PC의 제한된 실행 환경에서도 비슷한 메시지가 나타났으므로 메시지 하나만으로 원인을 확정하지 않습니다. 암호나 토큰이 들어간 로그는 가리고 필요한 오류 부분만 공유합니다.
