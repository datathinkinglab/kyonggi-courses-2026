첨부파일의 외부 CDN 의존성 구조 확인

유안타증권_지점장.html 파일은 별도의 이미지나 CSS 폴더 없이 단일 파일로 작동하지만, 아래 3가지 외부 CDN 라이브러리를 인터넷을 통해 불러옵니다.

1. Tailwind CSS (디자인/다크네이비 컬러 테마)
https://cdn.tailwindcss.com
2. Chart.js (PB 달성률 가로바 & 자산배분 도넛차트)
https://cdn.jsdelivr.net/npm/chart.js
3. Phosphor Icons (왕관, 빌딩, 경고 아이콘)
https://unpkg.com/@phosphor-icons/web

※ 따라서 오프라인 환경이나 사내 방화벽이 CDN을 차단하면 차트나 아이콘이 보이지 않을 수 있습니다 (슬라이드 24 & 27 검증 항목).

참고 | Streamlit과 React 앱 배포하기

GitHub에 코드를 저장하고, 앱에 맞는 실행 환경에 연결합니다.

먼저 구분하기

GitHub는 코드를 저장하는 곳입니다. GitHub Pages는 HTML·CSS·JavaScript 같은 정적 파일을 제공하며, 서버에서 Python을 실행하지 않습니다. Streamlit은 Python 실행 환경이 필요하고, React 화면은 보통 빌드한 정적 파일을 게시합니다.

① Streamlit: GitHub + Community Cloud

데이터 분석·시각화 코드가 들어 있는 app.py를 Python 환경에서 실행하고 웹 주소로 공유합니다.

my-app/
├── app.py
├── requirements.txt
└── data/sample.csv  (필요한 경우)

requirements.txt에 앱이 사용하는 패키지를 한 줄씩 적습니다. 예: streamlit, pandas, matplotlib. 실제 import와 파일 경로를 확인하고 필요한 데이터 파일도 준비합니다.

  1. 위 파일을 GitHub 저장소에 올립니다. 공개 저장소에는 비밀번호·API 키·개인정보를 올리지 않습니다.
  2. Streamlit Community Cloud에 로그인하고 GitHub를 연결합니다. 배포할 저장소에 필요한 권한이 있어야 합니다.
  3. Create app에서 기존 앱을 선택하고 저장소, 브랜치, 실행 파일 경로(예: app.py)를 지정합니다.
  4. 필요하면 Advanced settings에서 Python 버전과 Secrets를 설정하고 Deploy를 누릅니다.
  5. 생성된 streamlit.app 주소에서 데이터와 기능을 확인합니다. 이후 연결된 브랜치의 코드 변경은 앱에 반영됩니다.

Community Cloud는 무료로 시작할 수 있으나 자원 제한이 있습니다. 저장소 공개 여부와 앱의 접근 범위는 각각 확인하세요.

Streamlit 공식 배포 안내 ↗

② React: GitHub Pages에 정적 앱 배포

React 프로젝트는 보통 app.py가 아니라 JavaScript 또는 TypeScript로 작성합니다. 소스 전체를 GitHub에 올리고, 빌드한 결과물을 Pages에 게시합니다.

  1. package.json, 소스 파일, 잠금 파일 등 프로젝트를 GitHub 저장소에 올립니다.
  2. Vite 프로젝트를 https://사용자명.github.io/저장소명/에 게시한다면 vite.config.js의 base를 '/저장소명/'으로 설정합니다. 사용자 사이트나 사용자 지정 도메인의 루트에서는 보통 '/'를 사용합니다.
  3. 저장소의 Settings → Pages → Source에서 GitHub Actions를 선택합니다. Vite 공식 안내의 워크플로를 추가해 의존성 설치, 빌드, 배포가 실행되도록 합니다.
  4. Actions에서 완료 여부를 확인하고 Pages 주소를 열어 이미지·화면 이동·기능을 점검합니다. 이후 지정 브랜치에 변경 사항을 올리면 워크플로가 다시 실행됩니다.

위 설정은 Vite 프로젝트의 예입니다. 다른 React 도구는 빌드 명령과 출력 폴더를 해당 프로젝트에 맞게 확인하세요. 프로젝트 주소의 하위 경로와 화면 이동 방식에 따라 추가 설정이 필요할 수 있습니다.

Vite 공식 GitHub Pages 배포 안내 ↗

③ React의 다른 선택지와 서버가 필요한 경우

Vercel이나 Netlify에 GitHub 저장소를 연결해 React 프로젝트를 빌드·배포할 수도 있습니다. 서비스에서 저장소를 선택하고 빌드 설정을 확인한 뒤 배포 주소를 검증합니다.

React 화면에서 Python 분석이나 여러 사용자가 공유하는 데이터를 처리하려면 별도의 서버 또는 외부 서비스가 필요합니다. 화면과 서버를 각각 배포하고 연결하며, 인증·데이터 보관 방식도 확인합니다.

Vercel React 배포 안내 ↗

공개 전 확인: 실제 고객 정보와 비밀키를 제거하고, 배포 주소에서 다른 기기 접속과 주요 기능을 점검하세요. 플랫폼의 화면과 요금·제한은 변경될 수 있습니다.

부록 B. 강사용 사전 점검 & 부록 C. 공식 참고자료

부록 B. 강사용 수업 전 필수 점검 5계명

  1. 사용 권한이 있는 가상 HTML을 준비하고 원본(유안타증권_지점장.html)의 실제 조직명·수치·민감한 내용이 남지 않았는지 소스까지 확인한다.
  2. 가상 수치의 생성 목적, 의미, 단위(억원, %), 가정을 설명하고 화면에 표시한다.
  3. 테스트용 계정과 저장소로 현재 GitHub 메뉴, Pages 설정, 배포 및 삭제·관리 절차를 미리 확인한다.
  4. 외부 라이브러리(Tailwind, Chart.js, Phosphor Icons) 접속, 차트, 필터, 메모, 인쇄를 실습실 네트워크에서 점검한다.
  5. 수업용 계정 준비가 어려운 학생을 위해 조별 시연과 개별 설명·검증 기록 양식을 준비한다.
